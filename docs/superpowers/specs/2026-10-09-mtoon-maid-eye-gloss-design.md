# COM3D25.MToonMaid.Plugin 設計 v2.9（瞳の光沢）

日付: 2026-10-09
前提: `2026-10-09-mtoon-maid-hair-shadow-design.md`（v2.8）までの設計を引き継ぐ。ここに書いたことだけを変える。

## 背景

アニメ調の参考画像のような瞳の光沢感を出したい。参考画像の要素は次の 4 つ。

- A. 上まぶたの影: 瞳の上側が暗く沈むグラデーション
- B. 鏡面ハイライト: 大きな白い点と小さな点。視点に合わせて動く
- C. 瞳の下側の明るさ: 下側が明るく水色ににじみ、小さなきらめきの粒がある
- D. 全体のにじみ（ブルーム）

A・B・C を対象にする。D はポストエフェクトの領域なので対象外。

今の瞳は MToon に置き換えていない（半透明のため対象外）。2026-10-09 に実機で確かめた事実:

- 瞳は head スロットの `EyeL` / `EyeR` マテリアルで、シェーダーは `CM3D2/Toony_Lighted_Trans`（renderQueue 3000）。`_MainTex` は無限色の RenderTexture（256px）で、瞳の形と位置は MOD ごとに変わる
- `eye` の menu は顔によらず `テクスチャ変更 head 0 _MainTex … EYE_L` / `テクスチャ変更 head 1 _MainTex … EYE_R` と書かれている。head スロットのマテリアル番号 0 が左目、1 が右目になるのはゲーム全体の約束
- `eye_hi` の menu は `テクスチャ変更 head 2 _MainTex …` で、番号 2 は両目を覆う板 `SkinHi`（`CM3D2/Lighted_Trans`）。瞳のテクスチャへの合成ではない
- 瞳のテクスチャ自体（`eye` の menu）にも小さな点や下側の明るさが描かれている。これはそのまま使う

## 方式

瞳のマテリアルのシェーダーを専用の `COM3D25/MToonMaidEye` へ差し替える。瞳の外接矩形は C# 側でテクスチャのアルファから求めてシェーダーへ渡し、A〜C をその矩形で正規化した座標に描く。

比べた案:

- 瞳専用のシェーダーへ差し替える（採用）: 描画順が今と同じで、レンダラーも増えない。既存の差し替え・復元の作法に乗る
- ハイライト用の板を別に重ねる: レンダラーが増え、半透明どうし（まつ毛・`SkinHi`・涙）の描画順が破綻しやすい。瞳の形で切り抜くのも難しい
- 瞳の矩形を固定値にする: MOD の瞳の形や位置がずれると、影やハイライトが瞳から外れる

## シェーダー

### `COM3D25/MToonMaidEye`

描画の状態:

- 元の `Toony_Lighted_Trans` に合わせる。renderQueue は元の値を引き継ぎ、アルファブレンド（SrcAlpha / OneMinusSrcAlpha）で、深度は書かない。まつ毛・眉との前後関係を変えない
- 追加ライトのパス（ForwardAdd、加算）を持ち、光側を平らに照らす（README の追加ライトの方針に合わせる）。追加ライトのパスでは上まぶたの影と下側の明るさだけを描き、ハイライトときらめきは ForwardBase だけで描く（追加ライトの数だけ白が重なって飛ぶため）

基本の色:

- `_MainTex × _Color ×` 明るさ。明るさは顔の MToon の光側と同じ式（主光源の色と環境光）。光と影の境界は入れない（アニメ調の瞳でライトの向きにより瞳が半分暗くなるのを避ける）

瞳の座標:

- `_IrisRect`（xy = 外接矩形の UV の最小、zw = 大きさ）で UV を 0〜1 へ正規化する
- A と C はまぶたに沿うべきなので、テクスチャの上下（頭の上下）で描く
- B だけは画面の向きの座標で置く。画素ごとの `ddx` / `ddy` から画面の右・上が UV のどちら向きかを求め、正規化した瞳の座標をその向きへ写す。左右の目で UV が鏡像でも、頭を傾けても、ハイライトは画面上の同じ側に出る

効果（どれも `_MainTex` のアルファの内側だけに出し、白目へははみ出さない。どれにも基本の色と同じ明るさを掛け、暗いシーンで瞳だけが光らないようにする）:

- A. 上まぶたの影: 瞳の上端から「高さ」までを、影の色で乗算する。境界は「ぼかし」でなめらかにする
- C. 下側の明るさ: 瞳の下端から「高さ」までに、色をスクリーンで重ねる。同じ範囲に、シェーダーで作った固定の柔らかい粒（きらめき。瞳の幅の 0.12 ごとのセルの 3 割ほどに 1 つ）を加算する。細かいセルに硬い点を置くと規則的な格子に見えた（実機）
- B. ハイライト: 丸を 3 個まで置き、加算する。中心は白、ぼかしの部分は「にじみの色」（白のまま薄めると縁が灰色に濁って見えるため。ユーザーの要望）。それぞれ位置・大きさ・ぼかし・強さを持つ。強さ 0 の丸は描かない
- 視差: C# が渡す視線（ワールド、`_EyeGaze`）をビュー座標へ写し、その横と縦の成分に「視差」を掛けた分だけハイライトを反対向きへずらす。目が横（上下）を向くと、ハイライトが瞳の中で反対側へ寄る。0 で止まる

### `Hidden/COM3D25/MToonMaidHidden`

何も描かないシェーダー。`SkinHi`（eye_hi）を消すときに差し替える。マテリアルや menu には触らず、戻すときは元のシェーダーへ戻す。

### バンドル

2 本とも `UnityProject2022/Assets/Shaders/MToonMaid/` に置き、mtoon_bundle に入れる。`MToonShaderProvider` で MToon と一緒に読む。読めない・今のグラフィックス API で使えないときは、エラーを 1 回出して瞳の機能だけを無効にする（前髪の影と同じ作法）。ウィンドウの「目」タブは無効表示にする。

## C# の構成

### 新しく作るもの

- `Settings/EyeSettings`: 瞳の設定。`MaidSettings` に `eye` 要素として足す
- `Rendering/IrisBounds`: アルファの配列（幅・高さ・閾値）から外接矩形を UV で返す純粋な関数。Unity の型を使わずテストする（テストの net48 では Unity 2022 の `UnityEngine.CoreModule` を読めないため。`BumpMaskBaker` と同じ）。閾値を超える画素が無ければ UV 全体（0〜1）を返す
- `Rendering/EyeConverter`: 瞳のマテリアルを `MToonMaidEye` へ差し替え・元へ戻す。設定値を入れる。`SkinHi` を `MToonMaidHidden` へ差し替え・元へ戻す
- `ToonMaterialClassifier` の判定:
  - 瞳: スロットが `head`、マテリアル番号が 0 か 1、シェーダー名がちょうど `CM3D2/Toony_Lighted_Trans`（前方一致にすると `_NoZ` の瞳まで深度を比べるシェーダーへ差し替え、描画順が変わる）
  - ハイライトの板: スロットが `head`、元のシェーダー名がちょうど `CM3D2/Lighted_Trans`（SkinHi）で、マテリアル番号が 2、または `MPN.eye_hi_r` のファイル名が空でないときの 7。ゲームは `eye_hi_r` の「テクスチャ変更」を番号 7 へ向け直す（`Menu.ProcScript`）。古い顔の番号 7 は `bukkake`（`_NoZ`）なので、シェーダー名でも絞る（顔 MOD の番号 2 が別のマテリアルのときも消さない）
- head スロットの sub スロットは 1 つだけ（2026-10-09 に実機で確認）なので `GetSlot("head")` だけを見る

### 有効になる条件

メイドの「MToon にする」が ON で、かつ「目」タブの「瞳を光沢のシェーダーにする」が ON のとき。顔グループの ON / OFF やスロットの除外とは独立させる。`SkinHi` を消すのは、これに加えて「eye_hi を消す」が ON のとき。

### 走査（`MaidMToonController.Scan`）

- 瞳と `SkinHi` は MToon の `_entries` とは別の控えで管理する（ランプ・凹凸のマスクの処理に混ぜない）。控えには元のシェーダー・renderQueue・スロット・マテリアル番号・最後に求めた外接矩形とその鍵を持つ
- menu の shader コマンド等で元のシェーダーへ戻されたら差し替え直す
- 戻すときは `GameShaderBackup.Replace` で、ゲームの戻し先が自分のシェーダーになっていれば元のシェーダーへ補正する
- 例外になったマテリアルは MToon と同じく以後飛ばし、警告を 1 回出す

### 瞳の外接矩形

GPU からの読み戻しは同期で待つため、走査ごとには求めない。次のどれかが前回と違うときだけ求める:

- `_MainTex` の実体（インスタンス ID）
- `MPN.eye` のファイル名（無限色の RenderTexture は同じ実体のまま中身が描き変わるため）

外接矩形が見つからない（全面透明）ときは UV 全体を入れ、鍵を記録せず次の走査で求め直す（無限色の RT がまだ描かれていない場合に備える）。最初に見つからなかったフレームから 120 フレーム経っても見つからなければ、鍵を記録して止める（回数で区切ると走査の間隔を縮めたときに早く固定されるため）。読み戻しの例外は差し替えの失敗と分け、UV 全体として扱って 1 回だけ警告する。

他者（menu の shader コマンドなど）が瞳や板を別のシェーダーにしたら、それに従って控えから外す。戻すときは今のシェーダーが自分のシェーダーのときだけ元へ戻し、ゲームの戻し先は自分のシェーダーと照合して補正する（今のシェーダーと照合すると、shader コマンドで元へ戻された直後の OFF で戻し先に自分のシェーダーが残る）。

求め方: 64×64 の RenderTexture へ `Graphics.Blit` で縮小し、`ReadPixels` で読んだアルファを `IrisBounds` へ渡す。左右の目は別々に求める（同じテクスチャでも UV の配置が違いうるため）。縮小用の RT は求めるたびに一時確保して返す。

### 毎フレーム（既存の `Camera.onPreCull`）

瞳が有効なメイドだけ、視線をワールドで瞳のマテリアルへ渡す（`_EyeGaze`）。目のボーン（`trsEyeL` / `trsEyeR`）は外向きに傾けて置かれ、軸をそのまま使うと視線が常に外へずれる。ゲームは `localRotation = quaDefEye * Euler(...)` で目を回すので、`eye.rotation * Inverse(eye.parent.rotation * quaDefEye)`（既定の向きからの回転）を顔の正面 `trsHead.up` に掛けて求める（2026-10-09 に実機で、目が正面のとき顔の正面との内積 0.998 を確認）。マテリアル番号 0 は `trsEyeL`、1 は `trsEyeR`。ボーンが無ければ 0 を渡し、視差なしで描く。前髪の影の後に更新する（視線の例外で前髪の影を止めないため）。

### 後片付け

「瞳を光沢のシェーダーにする」の OFF・メイドの MToon の OFF で、瞳と `SkinHi` を元のシェーダーと renderQueue へ戻す。「eye_hi を消す」の OFF では `SkinHi` だけを戻す。メイドの破棄では控えを捨てるだけ（マテリアルも破棄済み）。プラグインの終了時は既存の MToon と同じく戻さず、読み戻し用の Texture2D だけを破棄する。

## 改訂 2026-10-10: ハイライトの追加・削除、くっきりした芯と色付きのにじみ、映り込み

実機で見たあとのユーザーの要望で、ハイライトと下側の表現を次のように変える。この節が上の記述（ハイライト 3 個固定・にじみの色の共通 1 色・きらめき）より優先する。

### ハイライト

- 0〜8 個を自由に持てる（シェーダーは固定長 8 の配列で受ける）。`highlights` が無いファイルは既定の 3 個、空の `highlights` は 0 個として読む。8 個を超える分は捨てる
- 1 個あたりの値:

| 表示名 | フィールド | 型・範囲・既定（新規に追加したとき） |
|---|---|---|
| 強さ | `strength` | float、0〜1、1 |
| 位置 X / Y | `x` / `y` | float、-0.5〜0.5（瞳の幅を 1 とした中心からの位置。画面の右・上がプラス）、0 / 0 |
| 大きさ W / H | `width` / `height` | float、0〜1（瞳の幅に対する直径）、0.1 / 0.1 |
| 色 | `color` | 色（楕円の内側＝芯の色）、#FFFFFF |
| ロール | `roll` | float、-180〜180（度。画面上で反時計回りがプラス）、0 |
| にじみの色 | `glowColor` | 色とアルファ（アルファはにじみの不透明度）、#A0B4FF・1 |
| にじみの強さ | `glowStrength` | float、0〜2（にじみの濃さの倍率。1 より上でにじみの色のアルファより濃くできる）、1 |
| にじみの幅 W / H | `glowWidth` / `glowHeight` | float、0〜0.3（瞳の幅に対する、楕円の横 / 縦の軸の向きに縁から外への幅。ロールに合わせて回る。`glowHeight` が無いファイルは `glowWidth` と同じ値で読む。外縁は「芯の半径 + W / H」の楕円なので、細長い楕円の斜めの向きでは 1 値だったときより少し細くなる）、0.05 / 0.05 |

- 描き方: 楕円の内側は「色」で、縁は 1 画素ぶんだけなめらかにする（くっきり）。縁の外側に、にじみの色を「にじみの幅 W / H」の楕円（芯の半径 + W / H）まで広げ、中心からの同じ向きで芯の縁から外縁までの割合に沿って二乗で薄くする（にじみの色のアルファを掛ける）。楕円の縁までの距離は `f / |∇f|`（f は楕円で正規化した中心からの距離 - 1）で近似する（正確な楕円の距離は計算が重い。`f × 短い方の半径` だと細長い楕円で長い軸の向きにぼけが伸びる）。幅か高さが 0 のハイライトは描かない
- 重ね方: ハイライト同士と、瞳の上へはスクリーン合成（`1 - (1 - 下)(1 - ハイライト)`）で重ねる（加算だとにじみの色が白へ飽和する。ユーザーの要望）。白目の上はブレンドが下の色を読めないため、ハイライトの濃さで重ねる（灰色ならスクリーンと一致する）
- 白目へのはみ出し: ハイライトは瞳のテクスチャのアルファで切り抜かない（ユーザーの要望）。ForwardBase の出力のアルファを `瞳のアルファ + ハイライトの濃さ × (1 - 瞳のアルファ)` にし、色は `(瞳の色 × 瞳のアルファ × (1 - ハイライトの色) + ハイライトの色) / アルファ` にして、ブレンドの結果が「瞳にハイライトをスクリーン合成したもの」になるようにする。ハイライトの濃さは色の RGB の最大値。上まぶたの影・下側の明るさは瞳の内側だけ。描けるのは瞳のメッシュの範囲までで、まぶたより奥の部分は顔の肌に隠れる
- 既定の 3 個は、参考画像に合わせて 大きい丸（青紫のにじみ）・小さい丸・右下の横長の楕円（ピンク寄りのにじみ）にする。値は実機で詰める
- 旧形式（`size` / `softness`、共通の `highlightGlowColor`）からの移行は作らない（未公開の機能のため）。旧形式の要素は読み飛ばされ、新しい値は既定になる

### 映り込み（廃止）

一度足した映り込み（角の丸い四角の半透明の面、`reflection`）は、ユーザーが使わないため機能ごと削除した。`reflection` の要素は読み飛ばす。

### まぶたの閉じ具合でハイライトを中央へ寄せる

| 表示名 | フィールド | 型・範囲・既定 |
|---|---|---|
| まぶたで中央へ | `lidFollow` | float、0〜1、0.5 |
| 中央の高さ | `lidCenter` | float、-0.5〜0.5、0（NaN は 0） |

- 閉じ具合はゲームがまばたきを足すとき（`TMorph.FixBlendValues_Face`）と同じく、`eyeclose`・`eyeclose2`〜 のブレンド値の合計を 1 で頭打ちにした値。まばたきも含む。番号 0 は「ブレンドが無い」の印として数えない。`BlendDataIdx_EyeClose` の全ての顔タイプの行を足す（今の顔タイプ以外の行はゲームが毎フレーム 0 にする。今の顔タイプは private で、CRC の顔では `TMorphSkin` の別のフィールドになるため読まない）
- 各ハイライトの Y を `lidCenter + (Y - lidCenter) × (1 - lidFollow × 閉じ具合)` にし、視差の Y にも同じ倍率を掛ける（`lidCenter` の高さへ寄せる。既定の 0 は瞳の中心）。一律に下へずらすと、笑顔のように下から閉じる目で下のハイライトが隠れるため。Y はハイライトの位置と同じ画面の上下で、頭を大きく傾けたときはまぶたの閉じる向きとずれる（承知のうえ）
- 閉じ具合は視線と同じくカメラの描画の前に毎フレーム入れる。全ハイライト共通の 1 値

### 視差

- 範囲を -1〜1 にする（ユーザーの要望）。マイナスにするとハイライトが目の向きと同じ側へ滑る。NaN は 0（視差なし）に丸める（下限の -1 にすると見た目が大きく変わるため）

### 削除

- きらめき（`sparkle` とシェーダーの粒）。参考画像に無いため。`sparkle` の要素は読み飛ばす
- 共通のにじみの色（`highlightGlowColor`）。ハイライトごとの `glowColor` に置き換える

### 目タブの UI

```
上まぶたの影  強さ / 色 / 高さ / ぼかし
下側の明るさ  強さ / 色 / 高さ / ぼかし
ハイライト    [1][2][3] [追加][削除]   (PostEffects のパラフィンのデータ番号の行と同じ作り)
              強さ / 色 / 位置 X[ ] Y[ ] / 大きさ W[ ] H[ ] / ロール / にじみの色 (アルファつき) / にじみの強さ / にじみの幅 W[ ] H[ ]
ハイライトの動き  視差 / まぶたで中央へ / 中央の高さ
```

- `X[ ] Y[ ]` と `W[ ] H[ ]` は、軸名のドラッグラベルと数値の入力欄を横に並べた 1 行（行の右端にリセット）。MTEUtils の `DrawVector2Row` は軸名が X / Y 固定で W / H に使えないため、`DrawFloatField`（ドラッグラベルつき）を 2 つ並べて自前で描く
- ハイライトが 0 個のときも、選んだハイライトの行は消さずに無効表示にする（入力欄キャッシュの番号がずれるため）
- [追加] は 8 個で無効、[削除] は 0 個で無効。追加すると新しいハイライトを選び、削除すると選択を 1 つ前へ寄せる
- 選択中の番号は、描く前に毎回範囲へ寄せる（メイドの切り替えやファイルの読み直しで個数が減っても範囲外を指さない）
- ハイライトの行のリセット（R）は、どの番号でも「新規の既定」（[追加] で足す値）へ戻す。既定の 3 個の初期値へ戻すのは、タブ全体の「目の調整値を既定に戻す」
- 番号の行は 8 個と [追加][削除] が最小幅 380 に収まる幅にする

## 改訂 2026-10-10 (2): 目タブのサブタブと瞳の色

ユーザーの要望で、目タブを 3 つのサブタブに分け、ゲームの瞳の色（エディットの「瞳の色」と同じパーツカラー）もここで変えられるようにする。

### サブタブ

```
瞳を光沢のシェーダーにする            (サブタブの上。どのサブタブでも出す)
[影・明るさ] [ハイライト] [瞳の色]
影・明るさ   上まぶたの影 / 下側の明るさ / 目の調整値を既定に戻す
ハイライト   eye_hi を消す / ハイライトの番号の行と各値 / ハイライトの動き (視差・まぶたで中央へ・中央の高さ) / 目の調整値を既定に戻す
瞳の色       [左右] [左] [右] / メイン: 色相・彩度・明度・コントラスト / 影: 割合・色相・彩度・明度・コントラスト
```

- 選んでいるサブタブはウィンドウが覚える（メイドを切り替えても変えない）。保存しない
- 「瞳のシェーダーを読めないため使えません」の表示は、影・明るさとハイライトのサブタブにだけ出す
- 瞳の色のサブタブは、瞳の光沢の ON/OFF・瞳の光沢のシェーダーの有無に関係なく使える（ゲームのパーツカラーを変えるだけのため）。MToon のシェーダー自体が読めないときはウィンドウ全体が使えない

### 瞳の色

- ゲームの `MaidParts.PARTS_COLOR.EYE_L` / `EYE_R` のパーツカラー（`MaidParts.PartsColor`）を `maid.Parts.GetPartsColor` / `SetPartsColor` で読み書きする。値はゲームのセーブに入り、プラグインの設定ファイルには持たない
- 範囲はエディットのスライダー（`ColorPaletteUIManager`）と同じ整数: 色相 0〜255、彩度 0〜255、明度 0〜510、コントラスト 0〜200、影の割合 0〜255。書くときに範囲へ丸める
- 書くときは読んだ `PartsColor` の各値だけを差し替え、`m_bUse` は残す（エディットは `m_bUse` を落とすが、色の更新には使われていないため、元の値を残す方が安全）
- 左右の選択はエディットと共有する `maid.status.eyePartsTab`（`LR` / `L` / `R`）に入れる
  - 左右（`LR`）: 左の値を表示し、書くときは左右の両方へ同じ値を書く。左右へ切り替えたときは左の値を右へ写す（エディットと同じ。右の色は失われる）
  - 左（`L`）/ 右（`R`）: それぞれの値を表示し、その目だけに書く
  - 左右が選ばれているのに左右の値が違う（エディットの外で変えられた）ときは、右へ切り替える（エディットのパレットを開いたときと同じ。右の色を黙って上書きしないため）。切り替えはサブタブを開いた時点で `eyePartsTab` に書く（ゲームのセーブに入る）
- 書き込み（`SetPartsColor` はゲームのテクスチャを作り直す）はウィンドウの描画中に行わず、ためておいて次の Update で行う。ためている間はためた値を表示する
- 毎回の描画でメイドの今の値を読み直す（メイドの切り替え・エディットでの変更に追従する）
- 行のリセット（R）は出さない（パーツカラーの既定値をゲームが持っていないため）
- 色の変更に対応していない瞳（色テーブルを使わないテクスチャ）では、書いても見た目は変わらない。エラーにはしない

## 改訂 2026-10-10 (3): 瞳の色をカラーピッカーで選ぶ

ユーザーの要望で、瞳の色のサブタブの色相・彩度・明度のスライダー（メイン・影）を、プラグインの色の行（見本・HEX・R・[編集] でカラーピッカー）に置き換える。

```
瞳の色       [左右] [左] [右]
             メイン: 色 (色の行) / コントラスト
             影:     割合 / 色 (色の行) / コントラスト
```

### パーツカラーと RGB の対応（実機で確認）

パーツカラーは、瞳のテクスチャの明るさ x（0〜255）から色を引く 256×1 の表になる。実機で表を読み戻した結果、HSL の着色と一致した。

- 明るさ: `L(x) = clamp((x − 128) × コントラスト / 100 + 128 + (明度 − 255), 0, 255) / 255`
- 色相: `色相 / 255`（0〜1 で一周。255 は 0 と同じ赤）
- 彩度: `彩度 / 255`（HSL の彩度）
- 影は、同じ式で作った影の色から、メインの色へ影の割合の幅で混ざる

色の行が表す色は「x = 128 の位置の色」= `HSL(色相/255, 彩度/255, clamp(明度 − 127, 0, 255)/255)` とする。コントラストはこの点の色を変えないため、色の行とは独立したスライダーのまま残す。

- 色 → 値: 選んだ RGB を HSL に直し、色相 = round(H × 255)、彩度 = round(S × 255)、明度 = round(L × 255) + 127（127〜382）
- 彩度が 0（灰色）のときは色相を元のまま残す。L が 0 か 1（黒か白）のときは色相と彩度を元のまま残す（RGB から決まらないため）
- 明度の 127 未満・382 超え（エディットでは 0〜510 まで選べる）は色では表せない。表示は黒か白で、色を触ったときに 127〜382 へ寄る。範囲外の色相（MOD など）は一周に収めて表示する
- 値は整数なので、色を選び直すと HEX が ±1〜2 ずれることがある
- 選んだ色から求めた値のままの間は、色の行とピッカーへ選んだ色をそのまま渡す（`EyePickedColor`）。値から求め直した色を渡すと、丸めでずれた色からピッカーが HSV を作り直し（灰色を通ると色相が赤になり、そのままドラッグを続けると瞳の色相も赤で上書きされる）、入力途中の HEX も書き換わるため。値がほかから変わったら（エディット・メイドや左右の切り替え）値から求めた色に戻す
- 色の行の R とピッカーのリセットは、今の色へ戻す（何も変わらない）。パーツカラーの既定値をゲームが持たないため。MTEUtils の色の行は R を隠せない
- ピッカーの同定キーは「目/瞳の色/メイン」「目/瞳の色/影」に固定し、メイドか左右が変わったら開いているピッカーを閉じる（キーにメイドや左右を含めるとピッカーの題に出て読めない。閉じないと前の対象の色を指したままになる）
- 書き込みを Update まで遅らせること、ためている間はためた値を表示することは、改訂 (2) と同じ

## 改訂 2026-10-10 (4): 瞳の色を編集前に戻す

ユーザーの要望で、瞳の色のサブタブに、編集前の色へ戻すリセットを足す。改訂 (2) の「行のリセット（R）は出さない」と改訂 (3) の「R は今の色へ戻す」は、この節で置き換える。

```
瞳の色       [左右] [左] [右]
             メイン: 色 [R] / コントラスト [R]
             影:     割合 [R] / 色 [R] / コントラスト [R]
             [瞳の色を編集前に戻す]
```

### 編集前の色

- メイドごと（`maid.status.guid`）に、そのメイドを [瞳の色] サブタブで初めて表示したときの左右の目の 9 値と左右の選択（`eyePartsTab`）を控える。左右の値が違うときに右へ切り替える処理（改訂 (2)）より前に控える
- シーンが切り替わったら（`LoadSceneMode.Single`。セーブのロード・エディットの出入りなど）控えを捨てる。次に表示したときの値が新しい編集前になる。追加読み込み（Additive）では捨てない（編集の途中で編集前が変わるため）
- 控えはプラグインの設定ファイルにもゲームのセーブにも入れない（ゲームを終えると消える）

### 行のリセット（R）

- 各行の R は、その行を編集前の値へ戻す。値は今表示している目の編集前の値（左右では左、右では右）。書き先は今の左右の選択に従う（左右なら両目）
- 色の行の R は色相・彩度・明度の 3 値を編集前の整数のまま戻す（色を経由しないので、色で表せない明度も元に戻る）。ピッカーのリセットも同じ
- コントラスト・影の割合のスライダーは、編集前の値を既定値にした R を出す

### 瞳の色を編集前に戻す

- 左右の目の 9 値と左右の選択を、控えた値へそのまま戻す（範囲へ丸めない）
- 書き込みは改訂 (2) と同じく Update まで遅らせる。ためている間は控えた値を表示する。ためている他の書き込み（スライダー・左右の切り替え）より優先し、それらは捨てる

### 既知の制約

- 色の行の R は、今の色と編集前の色が同じだと何もしない（MTEUtils の `ColorFieldCache.ResetColor` が同じ色なら呼び返さない）。色で表せない明度や、灰色で色相だけが違うときは、R では整数が戻らない。[瞳の色を編集前に戻す] で戻す
- スライダーの R は 0〜上限へ丸める（MTEUtils のスライダーの丸め）。範囲外の編集前の値（MOD など）は [瞳の色を編集前に戻す] で戻す
- [瞳の色を編集前に戻す] のあと、編集前が「左右」で左右の色が違うときは、次の表示で改訂 (2) どおり「右」に切り替わる
- エディットのプリセット適用（`CharacterMgr.PresetSet`）など、シーンを切り替えずにパーツカラーを変える操作は編集として扱い、控えを取り直さない。戻すとその操作の前の色になる
